# 拉取模型失败时在弹窗列举逐跳请求与响应

- 日期：2026-11-26
- 状态：生效中
- 来源：用户反馈——失败弹窗只有一句结论，看不出请求打到哪个 URI、上游回了什么

## 结论

`fetch_provider_models_direct` 的 wire 返回从「成功 = URL + models，失败 = reject」
扩展为：

- 成功：`url` + `models`，`attempts` 记录完整回退轨迹；
- 候选全部失败：不 reject，返回 `error` 非空、`url`/`models` 为空的结果，
  `attempts` 按请求顺序带出每一跳的 URL、HTTP 状态与响应摘要。

前端失败弹窗在错误摘要下列举每次请求：`GET <url>` + `HTTP <code> <text> · <响应摘要>`；
传输层失败（`status=0`）显示「未收到响应：请求超时/连接失败」。

## 为什么失败走返回值

Wails 的 error 只能带一条字符串，Promise reject 后结果载荷全部丢弃，弹窗拿不到逐跳
诊断。入参校验（空 Key、空 Base URL）仍走 error：没有发请求就没有诊断可列。

## 脱敏边界（取代此前「4xx/5xx 不读响应体」的注释口径）

- 非 2xx 响应体此前完全不读；现在只读前 4KB 生成展示摘要，且把本次请求的 API Key
  明文替换成 `******` 后才进入结果、错误串与展示。
- 日志仍只记 URL 与状态码，不落响应体。
- 2xx 但 body 不是模型列表时，响应体开头与上游 `msg/message` 同样先脱敏。
- 传输层错误不展示原始错误串（可能带出请求信息），只给超时/连接失败的粗分类。

## 展示口径

- 响应摘要单行化并截断到 1000 字符；列表区固定高度内滚动，不撑开弹窗。
- URL 是主信息：等宽字体、完整换行，不做省略截断。
